Module 02 · Administrer la machine

Installer et administrer Debian 13

Un serveur ne se gère pas avec un compte partagé. Ce module crée un compte administrateur nominatif, montre comment lire et régler les permissions Unix, et met le système à jour sans casser l'accès.

Module 02 Modifie la machine votre serveur, pas celui d'un autre Prérequis module 01
Ce module modifie le système. Chaque commande s'exécute sur une machine dont vous êtes responsable. Conservez toujours un accès fonctionnel (session ouverte, console de secours de l'hébergeur) avant de modifier les comptes ou l'authentification.

1. Objectif du module

À la fin de ce module, vous administrez Debian 13 avec un compte nominatif, des droits maîtrisés et un système à jour.

  • Créer un compte administrateur nominatif et vérifier son droit sudo.
  • Lire une ligne de permissions et savoir la traduire.
  • Régler les droits par défaut avec umask.
  • Protéger un fichier sensible par des droits minimaux.
  • Mettre à jour le système avec APT sans casser l'accès.
Un seul compte à la fois. Un compte partagé ne dit jamais qui a fait quoi. Un compte nominatif, oui : c'est la base de toute traçabilité.

2. Prérequis

Trois choses avant de commencer.

  • Le module 01 est terminé : une session SSH vérifiée s'ouvre sur la machine.
  • Vous disposez d'un compte capable d'utiliser sudo (ou d'un accès à la console de secours).
  • Vous savez ouvrir la console de secours de l'hébergeur : c'est le filet de sécurité si les comptes sont mal modifiés.
Règle de survie. Ne fermez jamais votre session actuelle avant d'avoir ouvert une seconde session avec le nouveau compte et vérifié qu'elle fonctionne.

3. Étape 1 — Créer le compte administrateur nominatif

Objectif : disposer d'un compte personnel capable d'utiliser sudo, sans perdre l'accès actuel.

Action : relevez d'abord votre situation, puis créez le compte.

Sur le serveur lecture seule

id
sudo -v

id affiche votre utilisateur, votre UID et vos groupes. sudo -v rafraîchit et teste le droit sudo : s'il passe sans erreur, votre accès d'administration est confirmé.

Action : créez le compte nominatif et autorisez-le à administrer.

Sur le serveur modifie la machine nom à adapter

sudo adduser admin
sudo usermod -aG sudo admin
id admin
sudo -l -U admin

adduser crée le compte et demande un mot de passe : remplacez admin par votre nom ou vos initiales. usermod -aG sudo ajoute ce compte au groupe sudo ; le -a est essentiel, sinon les autres groupes du compte seraient écrasés.

Vérification : id admin liste sudo parmi les groupes, et sudo -l -U admin affiche les commandes autorisées. Ouvrez ensuite une nouvelle session avec ce compte et lancez sudo -v avant de fermer celle-ci.

En cas d'erreur : admin is not in the sudoers file signifie que le compte n'est pas encore membre de sudo, ou que la session est trop ancienne — déconnectez-vous et reconnectez-vous. Retour arrière : sudo deluser --remove-home admin.

Ne supprimez jamais le dernier compte capable de sudo. Vérifiez toujours qu'un second compte administrateur fonctionne avant d'en retirer un.

4. Étape 2 — Lire et interpréter les permissions

Objectif : savoir qui peut lire, écrire ou exécuter un fichier.

Chaque fichier a un propriétaire, un groupe et trois séries de droits : pour le propriétaire (u), le groupe (g) et les autres (o). Chaque série vaut r (lire), w (écrire), x (exécuter). 

install -d -m 750 ~/demo-perms
touch ~/demo-perms/rapport.txt
chmod 640 ~/demo-perms/rapport.txt
ls -l ~/demo-perms
stat -c '%a %U %G %n' ~/demo-perms/rapport.txt

La notation octale se lit chiffre par chiffre : 6 = lire + écrire (4+2), 4 = lire seul, 0 = aucun droit. Donc 640 = propriétaire rw-, groupe r--, autres ---. 750 ajoute le droit d'exécuter, nécessaire pour traverser un répertoire.

Vérification : stat renvoie 640 pour rapport.txt et 750 pour le répertoire. Les deux commandes disent la même chose sous deux formes : symbolique (ls -l) et octale (stat).

En cas d'erreur : Operation not permitted lors d'un chown est normal : seul root peut changer le propriétaire d'un fichier. Un simple chmod sur vos propres fichiers ne demande pas sudo.

5. Étape 3 — umask et droits par défaut

Objectif : que les nouveaux fichiers ne soient pas créés trop ouverts.

Action : lisez vos droits par défaut, puis durcissez-les.

Sur le serveur modifie la session

umask
umask -S
umask 027
touch ~/demo-perms/essai.txt
stat -c '%a %n' ~/demo-perms/essai.txt

umask indique les droits retirés à la création : 022 laisse un fichier en 644. Une umask de 027 donne 640 pour les fichiers et 750 pour les répertoires — exactement la convention visée pour le projet.

Vérification : stat renvoie 640 pour essai.txt. Le changement ne dure que pour la session courante : pour le rendre permanent, ajoutez umask 027 à la fin de ~/.profile du compte concerné.

En cas d'erreur : si la valeur revient à l'ancienne après reconnexion, c'est que umask 027 n'a pas été écrit dans ~/.profile. Une umask trop restrictive (077) peut empêcher un service de lire ses propres fichiers : vérifiez toujours avec le compte d'exécution concerné.

6. Étape 4 — Protéger un fichier sensible

Objectif : qu'un fichier de configuration ne soit lisible que par qui de droit.

Action : créez le répertoire du projet et un fichier d'exemple avec des droits minimaux.

Sur le serveur modifie la machine

sudo install -d -m 750 /srv/apps
sudo install -m 640 /dev/null /srv/apps/exemple.env
stat -c '%a %U %G %n' /srv/apps/exemple.env

install crée en fixant directement le mode : c'est plus sûr qu'un touch suivi d'un chmod, qui laisse une fenêtre pendant laquelle le fichier est trop ouvert. /dev/null sert seulement de source vide pour créer le fichier.

Vérification : stat affiche 640 root root. L'attribution du groupe applicatif (root:reactapp, etc.) interviendra au module 06, quand les groupes existeront.

Un secret lisible par tous est un secret public. Un chmod 644 sur un fichier d'environnement rend son contenu lisible par n'importe quel compte de la machine. Aucun secret ne doit être versionné dans Git (module 08).

En cas d'erreur : Permission denied sur /srv/apps signifie que sudo a été oublié ; la création d'un répertoire dans /srv est réservée à root.

7. Étape 5 — Mettre à jour Debian en sécurité

Objectif : appliquer les correctifs sans surprise ni rupture de service.

Action : relevez ce qui est disponible avant d'appliquer.

Sur le serveur lecture seule

sudo apt update
apt list --upgradable
df -h /

Action : appliquez ensuite les mises à jour.

Sur le serveur modifie la machine

sudo apt upgrade
sudo apt autoremove --dry-run

apt update rafraîchit la liste des paquets ; apt upgrade installe les versions disponibles sans supprimer de paquet. df -h / vérifie que le disque a de la place, et le mode --dry-run montre ce que ferait un nettoyage sans rien supprimer.

Vérification : apt list --upgradable ne renvoie plus de paquet en attente après la mise à jour, et le service choisi (SSH) répond toujours — testez-le depuis une seconde session.

En cas d'erreur : dpkg was interrupted se répare avec sudo dpkg --configure -a. Espace insuffisant : lisez df -h / et nettoyez le cache avec sudo apt clean — jamais en supprimant une version applicative (module 10).

À savoir. apt full-upgrade peut supprimer des paquets pour résoudre des dépendances. Lisez la liste affichée avant de confirmer. Les avis de sécurité de Debian sont publiés sur debian.org/security.

8. Problèmes courants

Symptôme, cause probable, action.

Problèmes courants : symptôme, cause probable et action
SymptômeCause probableQue faire
admin is not in the sudoers file Le compte n'est pas membre du groupe sudo, ou la session date d'avant l'ajout Vérifiez id admin, puis reconnectez-vous
Permission denied sur un fichier pourtant lisible Un répertoire parent n'a pas le droit x : le chemin est infranchissable Contrôlez chaque niveau du chemin avec namei -l chemin
Un service ne démarre plus après un chmod Les droits ont été resserrés sous le seuil nécessaire au compte d'exécution Relevez le compte du service (User=) et testez la lecture avec lui
Les nouveaux fichiers sont en 644 umask 027 n'a pas été rendue permanente Ajoutez-la à la fin de ~/.profile du compte concerné
dpkg was interrupted Une mise à jour précédente a été interrompue sudo dpkg --configure -a, puis relancez la mise à jour
Le disque se remplit pendant une mise à jour Cache APT volumineux ou journaux qui grossissent df -h /, sudo apt clean, puis contrôlez les journaux (module 11)

9. Checklist finale

Ce module est terminé lorsque les six points suivants sont vrais.

  • Le compte administrateur nominatif existe et id le confirme.
  • sudo -l -U sur ce compte montre un droit d'administration limité, et un test dans une seconde session réussit.
  • Vous savez traduire une permission symbolique (drwxr-x---) en valeur octale.
  • La umask cible (027) est appliquée et écrite dans le profil si elle doit durer.
  • Un fichier de configuration d'exemple est en 640, jamais en 644.
  • Le système est à jour, le disque a de la place, et l'accès SSH fonctionne toujours.
Et ensuite ? Le module 03 durcit l'accès : clé SSH, désactivation de la connexion directe de root, comptes de déploiement et pare-feu couvrant IPv4 et IPv6.
